安装、升级、卸载接口文档

本站仅提供目录和 CRX 文件；网页不能直接修改浏览器的插件目录。安装、升级、卸载通过逐风浏览器在本站授权的 chrome.* 接口完成，并由原生安装器校验和确认。整个流程不查询 Google 商店。

运行前提

  1. 双击 start.command（macOS）或 start.bat（Windows），Linux 运行 ./start.sh；把 CRX3 放在 packages/。
  2. 公网 HTTPS 页面使用新版逐风的 chrome.nomadSignedExtensions，仅支持含可信发布签名的包。随机域名不会自动获得 webstorePrivate 权限。
  3. 本机普通 CRX 安装、升级和取包进度使用 webstorePrivate：让逐风 Test 构建以 --apps-gallery-url=http://127.0.0.1:18731/ 启动并打开此地址；可通过 ARUPA_BROWSER 配置启动脚本。普通 Chrome 不支持这些安装接口。

安装、卸载、应用升级必须由用户点击触发；隐身页面和已失效的标签页会被拒绝。原生确认框不能由网页绕过。

网站 HTTP 接口（只读）

接口返回用途
GET /api/catalog?platform=desktop|androidJSON：packages[]、errors[]扫描 packages/*.crx；先过滤平台，再选同 ID 最高版本。默认 desktop。
GET /api/package?id=<32位插件ID>&platform=desktop|android&sha256=<摘要>application/x-chrome-extension按 ID 和平台取包；sha256 可选，提供时必须与当前包一致，否则返回 409。
GET /api/healthJSON：服务状态与标识供一键启动脚本识别已运行的 Demo 服务。
GET /api/runtime实例 ID、运行状态、本机/局域网 URL、隧道 state / publicUrl / error供 start.* status 和页面显示当前地址；不返回控制凭据或包目录路径。

packages[] 每项包括 id、name、version、manifest、sha256、size、file、signedProduct、platforms 和 requirements。signedProduct 是包内发布元数据的路由提示，不代表签名已通过验证；platforms 根据 MiVPN 引擎文件区分桌面/Android，通用扩展默认两者。requirements 仅提示已扫描到的默认启用规则需求，例如 responseStageRules；它不是浏览器的兼容性或安装校验结果。无效 CRX 在 errors[] 中返回文件名及原因；包接口的 400、404、409 分别表示参数无效、未找到、摘要不符或读取时文件已变化。所有 HTTP 接口都不执行安装或卸载。

商店启停

命令入口统一为 start.sh、start.command、start.bat。不带参数时启动并打开页面；追加 status 查看地址与日志，追加 restart 重启，追加 stop 同时停止服务和隧道。例如 ./start.sh status、start.bat stop。重启沿用保存的设置，额外参数覆盖对应值；使用 --no-open 可不打开浏览器。公网域名在真正重启后变化，重复启动保持域名。

运行记录位于 .runtime/。仅启停脚本通过带私有凭据的回环请求调用 POST /_control/stop；网页不能使用该控制接口。旧版或手动运行的前台实例请在原终端停止，脚本不会终止未知进程。

公网 HTTPS：发布签名安装

Demo 优先为含发布签名元数据的包选择 chrome.nomadSignedExtensions。页面必须是顶层 HTTPS 页面，取包 URL 必须同源；浏览器匿名取包且不跟随重定向。仅有普通 CRX3 作者签名的包不能走此通道，网页也不能代替发布方签名。

// 点击事件内立即调用，不要先 await fetch 或延迟调用。
const packageUrl = new URL('/api/package', location.origin);
packageUrl.searchParams.set('id', item.id);
packageUrl.searchParams.set('platform', 'desktop'); // Android 页面用 android
packageUrl.searchParams.set('sha256', item.sha256);
chrome.nomadSignedExtensions.install({
  extensionId: item.id, packageUrl: packageUrl.href, expectedSha256: item.sha256
}, result => {
  if (chrome.runtime.lastError) return; // 失败/取消均保留原错误
  // 校验 result.extensionId、product、version 与目录相符，再查 getStatus。
});

chrome.nomadSignedExtensions.getStatus(item.id, status => {
  if (chrome.runtime.lastError) return;
  // { state: 'absent'|'installed'|'disabled', extensionId, product?, version? }
});

// 另一次用户点击；浏览器显示原生卸载确认。
chrome.nomadSignedExtensions.uninstall(item.id, () => {
  if (!chrome.runtime.lastError) location.reload();
});

getStatus 的 product、version 是可选信息，描述当前已安装的扩展，不要求等于商店当前包的元数据。页面严格核对 extensionId 和 state；缺少版本时显示“已安装（版本未知）”并暂停版本比较。install 的成功回执仍须与本次所选包的 ID、产品和版本一致。

install 回调成功表示整次安装完成，不再调用 completeInstall；Demo 还会重新查询并核对安装状态。此通道目前没有进度查询、checkUpdate 或 applyUpdate，不能复用下述 webstorePrivate 的进度接口；网页显示取包/验签等待提示，出现新版时提示手动卸载后重装。以下章节描述本机目录通道。

查询安装状态

chrome.management.getAll(items => {
  if (chrome.runtime.lastError) throw new Error(chrome.runtime.lastError.message);
  // 按 id 匹配 catalog.packages；items 中的 version、enabled 用于状态显示。
});

版本大于已安装版本时显示“可升级”；已安装但 enabled === false 时显示“已停用”。

安装

  1. 从 /api/catalog 读取所选 CRX 的 id、manifest 和 name。
  2. 在点击事件中立即调用 beginInstallWithManifest3，等待浏览器验证包和弹出原生授权框。
  3. 回调结果是空字符串且没有 chrome.runtime.lastError 时，在同一标签页调用 completeInstall；随后重新查询安装状态。
chrome.webstorePrivate.beginInstallWithManifest3({
  id: item.id,
  manifest: JSON.stringify(item.manifest),
  localizedName: item.name
}, result => {
  if (chrome.runtime.lastError || result !== '') return; // 安装未获批准
  chrome.webstorePrivate.completeInstall(item.id, () => {
    if (!chrome.runtime.lastError) location.reload();
  });
});

浏览器会校验 CRX3 作者签名、插件 ID、实际清单与页面预览一致性、权限及 DNR 规则。授权只绑定当前配置和标签页，且有时效；不能把 completeInstall 当作独立安装接口使用。

查询取包进度

若浏览器提供 chrome.webstorePrivate.getOperationProgress，点击时用 crypto.randomUUID() 生成本次操作的 operationId。新装将它放入 beginInstallWithManifest3 的详情对象，更新检查用 checkUpdate(id, { operationId }, callback)。在原回调完成前，从发起操作的同一页面调用 getOperationProgress(operationId, callback)，建议间隔 300 毫秒。旧浏览器沿用原调用形式。

{ progress: { operationId, operation, extensionId, stage, receivedBytes, totalBytes? } }

operation 为 install 或 update_check。阶段包括 preparing、downloading、verifying。新装还可进入 opening_confirmation、awaiting_user_confirmation。总大小未知时省略 totalBytes；操作尚未开始或已结束时返回 {}。命中更新暂存包时直接校验。安装批准、更新检查结果、错误和取消仍由原回调处理。

升级

  1. 把同一作者签名、同一插件 ID 的更高版本 CRX 放入 packages/，刷新列表。
  2. 点击“准备升级”调用 checkUpdate(id)。只有返回 state: "ready" 或 "permission_required" 且版本与目录一致，页面才显示“升级”。
  3. 点击“升级”调用 applyUpdate(id)；若新增权限，浏览器会再次请求原生确认。返回 true 后重新查询状态。
// “准备升级”按钮的点击事件：
chrome.webstorePrivate.checkUpdate(item.id, status => {
  if (chrome.runtime.lastError) return;
  // status: { state, version, errorCode }
  if (['ready', 'permission_required'].includes(status.state)) {
    // 页面显示“升级”按钮；不要在此回调中自动调用 applyUpdate。
  }
});

// “升级”按钮的另一次点击事件（必须保留用户激活）：
chrome.webstorePrivate.applyUpdate(item.id, applied => {
  if (applied && !chrome.runtime.lastError) location.reload();
});

示例包：先安装 packages/nomad-demo-1.0.crx；再把 samples/nomad-demo-1.1.crx 放进 packages/。浏览器按目录包的版本、大小和 SHA-256 校验升级，不使用 Google 商店的升级队列。

卸载

chrome.management.uninstall(item.id, { showConfirmDialog: true }, () => {
  if (!chrome.runtime.lastError) location.reload();
});

浏览器总会显示原生卸载确认；即使网页传入 showConfirmDialog: false 也不能跳过。用户取消时回调中可通过 chrome.runtime.lastError 得到失败原因。

错误与安全边界

浏览器接口的异步错误通过 chrome.runtime.lastError.message 返回；安装预检也可能返回非空结果码。常见原因包括用户取消、当前标签页失效、权限变化、签名或清单不匹配、目录包变化、扩展正在使用。页面应重新读取目录及安装状态后再重试，不能凭按钮状态推断安装成功。

当浏览器只返回 dnr_package_invalid 时，本站不会把它解释为 CRX 损坏，也不会仅凭目录扫描断定内核缺少哪项能力。页面会保留原始错误码；若目录扫描发现响应头匹配规则，只将其作为排查线索。只有浏览器明确返回 dnr_kernel_capability_unavailable 时，才提示缺少内核能力。

本站监听 0.0.0.0:18731，可通过本机、局域网或当前隧道访问。它不接受上传，也没有执行安装/升级/卸载的 HTTP 写接口。chrome.webstorePrivate 仅向特定商店页面开放；公网签名安装由 chrome.nomadSignedExtensions 提供，两者的授权和能力不同。
